# 프로젝트: 태그 및 필터 기능이 있는 할 일 관리 위젯

## [1단계] 역할 지정 (Role Prompting)

당신은 10년 이상의 경력을 가진 시니어 프론트엔드 개발자이자 UI/UX 디자이너입니다.

당신의 역할은 사용자가 직관적으로 할 일을 등록하고 관리할 수 있는 웹 기반 To-Do List 위젯을 개발하는 것입니다.

다음 원칙을 준수해 주세요.

- 초보자도 쉽게 이해하고 사용할 수 있는 인터페이스를 설계합니다.
- 기능 구현뿐 아니라 디자인과 사용자 경험도 중요하게 고려합니다.
- 유지보수가 쉽도록 코드를 구성하고 주요 부분에 한국어 주석을 작성합니다.
- 실제로 모든 기능이 정상 작동하는 완성된 웹 애플리케이션을 제작합니다.
- 불필요하게 복잡한 기술이나 기능은 추가하지 않습니다.

---

## [2단계] 프로젝트 목표 및 개발 환경

### 프로젝트 목표

개인이 해야 할 일을 등록하고, 각 할 일에 태그를 부여하며, 태그 및 완료 상태를 기준으로 원하는 할 일만 확인할 수 있는 **개인용 할 일 관리 위젯**을 제작합니다.

### 개발 기술

- HTML5
- CSS3
- JavaScript (Vanilla JS)
- LocalStorage (데이터 저장)

React, Vue 등의 프레임워크나 별도의 백엔드 서버 및 데이터베이스는 사용하지 않습니다.

프로젝트는 다음 파일로 구성해 주세요.

- index.html : 화면 구조
- style.css : 디자인 및 반응형 스타일
- script.js : 할 일 관리 및 필터 기능

index.html을 브라우저에서 실행하면 모든 기능을 사용할 수 있어야 합니다.

## [3단계] 필수 기능 구현

### 기능 1. 할 일 등록

사용자가 새로운 할 일을 등록할 수 있어야 합니다.

- 할 일 내용을 입력하는 텍스트 필드
- 태그를 지정하는 선택 메뉴
- 추가 버튼
- Enter 키로 등록 가능
- 내용이 비어 있으면 등록되지 않도록 검증

기본 태그는 다음 5개입니다.

- 공부 📚
- 운동 💪
- 개인 🏠
- 업무 💼
- 기타 📌

하나의 할 일에 태그 하나를 지정할 수 있도록 구현합니다.

### 기능 2. 할 일 목록

등록된 할 일을 카드 또는 리스트 형태로 표시합니다.

각 항목에는 다음 정보가 나타나야 합니다.

- 완료 여부를 표시하는 체크박스
- 할 일 내용
- 태그 이름과 색상 배지
- 수정 버튼
- 삭제 버튼

완료된 할 일은 체크 표시와 취소선을 적용하고, 미완료 항목과 시각적으로 구별합니다.

### 기능 3. 태그별 필터

사용자는 다음 필터 버튼을 통해 할 일을 구분할 수 있어야 합니다.

[전체] [공부] [운동] [개인] [업무] [기타]

- 전체: 모든 할 일 표시
- 공부: 공부 태그만 표시
- 운동: 운동 태그만 표시
- 개인: 개인 태그만 표시
- 업무: 업무 태그만 표시
- 기타: 기타 태그만 표시

선택된 필터는 색상이나 배경으로 명확하게 구별해 주세요.

### 기능 4. 완료 상태 필터

태그 필터와 별개로 다음 상태 필터를 제공합니다.

[전체] [진행 중] [완료]

태그 필터와 완료 상태 필터는 동시에 적용되어야 합니다.

예를 들어 공부 태그와 진행 중 필터를 동시에 선택하면, 공부 태그가 지정된 미완료 할 일만 표시해야 합니다.

### 기능 5. 할 일 수정 및 삭제

- 수정 버튼 클릭 시 기존 내용을 편집할 수 있어야 합니다.
- 수정 과정에서 태그도 변경할 수 있어야 합니다.
- 삭제 버튼 클릭 시 해당 항목을 삭제합니다.
- 삭제 전 확인 메시지를 제공합니다.

### 기능 6. 진행 현황 표시

화면 상단에 다음 항목을 표시합니다.

- 전체 할 일 개수
- 완료한 할 일 개수
- 남은 할 일 개수
- 전체 할 일 기준 완료 진행률(%)

진행률은 Progress Bar 형태로 시각화합니다.

완료 여부가 바뀌면 통계도 즉시 업데이트되어야 합니다.

### 기능 7. 데이터 저장

LocalStorage를 사용하여 다음 정보를 저장합니다.

- 할 일 내용
- 태그
- 완료 상태
- 고유 ID

브라우저를 새로고침하거나 닫았다가 다시 실행해도 저장된 할 일 목록이 유지되어야 합니다.

## [4단계] Few-shot 예시 (입력 및 예상 결과)

다음 예시를 기준으로 프로그램의 동작을 구현해 주세요.

### 예시 1. 할 일 등록

사용자 입력:
- 할 일: "파이썬 과제 완료하기"
- 태그: "공부"
- 추가 버튼 클릭

예상 결과:
- 새로운 할 일이 목록에 추가됩니다.
- "파이썬 과제 완료하기"라는 내용이 표시됩니다.
- 파란색의 "공부" 태그가 함께 표시됩니다.
- 기본 상태는 미완료입니다.
- 전체 할 일 개수가 1 증가합니다.

### 예시 2. 태그 필터링

현재 등록된 할 일:
1. 파이썬 과제 완료하기 / 공부 / 미완료
2. 헬스장 가기 / 운동 / 미완료
3. 프로젝트 보고서 작성 / 업무 / 완료
4. 자료구조 복습하기 / 공부 / 완료

사용자 행동:
- "공부" 필터 버튼 클릭

예상 결과:
- "파이썬 과제 완료하기"
- "자료구조 복습하기"

위 두 항목만 화면에 나타납니다.

운동과 업무 태그의 할 일은 삭제되지 않고 일시적으로 숨겨집니다.

### 예시 3. 복합 필터링

현재 선택된 조건:
- 태그 필터: 공부
- 완료 상태 필터: 진행 중

예상 결과:
- "파이썬 과제 완료하기"만 표시됩니다.

"자료구조 복습하기"는 완료된 상태이므로 화면에 나타나지 않습니다.

### 예시 4. 완료 상태 변경

사용자 행동:
- "파이썬 과제 완료하기"의 체크박스를 클릭

예상 결과:
- 해당 할 일이 완료 상태로 변경됩니다.
- 할 일 텍스트에 취소선이 적용됩니다.
- 완료 개수가 1 증가합니다.
- 남은 할 일 개수가 1 감소합니다.
- 진행률이 즉시 갱신됩니다.
- 현재 '진행 중' 필터가 적용되어 있다면 해당 항목은 목록에서 사라집니다.

### 예시 5. 데이터 유지

사용자 행동:
- 할 일 3개를 등록합니다.
- 하나를 완료 처리합니다.
- 브라우저를 새로고침합니다.

예상 결과:
- 할 일 3개가 그대로 유지됩니다.
- 완료된 항목의 상태도 유지됩니다.
- 진행 현황이 저장된 데이터를 기준으로 정확히 표시됩니다.

위 예시들은 단순한 설명이 아니라 실제 구현해야 하는 기능의 동작 기준입니다.

## [5단계] UI/UX 디자인

다음 디자인을 적용해 주세요.

### 전체 디자인
- 모던하고 미니멀한 생산성 관리 앱 스타일
- 밝은 화이트 및 라이트 그레이 배경
- 블루 또는 인디고 계열의 주요 강조 색상
- 부드러운 그림자와 둥근 카드 디자인
- 한국어 가독성이 좋은 폰트 사용
- 직관적인 아이콘과 버튼 배치

### 화면 구성

상단:
- 앱 제목: "My Task Manager"
- 부제목: "오늘의 할 일을 계획하고 관리해 보세요."

진행 현황:
- 전체 / 완료 / 남은 할 일 통계 카드
- 완료 진행률 바

할 일 입력:
- 내용 입력 필드
- 태그 선택 메뉴
- 할 일 추가 버튼

필터 영역:
- 태그별 필터 버튼
- 완료 상태별 필터 버튼

할 일 목록:
- 체크박스
- 내용
- 태그 배지
- 수정 / 삭제 아이콘 버튼

### 추가 디자인 요구사항
- 태그마다 서로 다른 색상을 사용합니다.
- 마우스를 올리면 버튼과 카드가 자연스럽게 반응합니다.
- 할 일이 하나도 없다면 "등록된 할 일이 없습니다."라는 안내 문구를 표시합니다.
- 필터 결과가 없을 때는 "해당 조건의 할 일이 없습니다."라고 표시합니다.
- 모바일에서도 정상적으로 사용할 수 있는 반응형 레이아웃을 적용합니다.
- 모든 버튼은 실제 기능과 연결되어야 하며 장식용 버튼을 만들지 않습니다.

## [6단계] 개발 작업 순서

아래 순서에 따라 단계적으로 개발해 주세요.

### Step 1. 프로젝트 구조 설계
- 프로젝트 파일을 생성합니다.
- HTML, CSS, JavaScript 파일을 연결합니다.
- 전체 화면 구조를 구성합니다.

### Step 2. 기본 UI 제작
- 제목 및 진행 현황 영역을 구현합니다.
- 할 일 입력 영역을 만듭니다.
- 태그 필터와 상태 필터를 배치합니다.
- 할 일 목록 디자인을 완성합니다.

### Step 3. 핵심 기능 구현
- 할 일 추가
- 할 일 수정
- 할 일 삭제
- 완료 상태 변경
- 입력값 검증

### Step 4. 태그 및 필터 구현
- 기본 태그 5개를 구현합니다.
- 태그별 필터를 적용합니다.
- 완료 상태 필터를 구현합니다.
- 두 필터가 동시에 작동하도록 구현합니다.

### Step 5. 데이터 저장
- LocalStorage 저장 기능을 구현합니다.
- 새로고침 시 저장된 데이터를 불러옵니다.
- 추가, 수정, 삭제 및 완료 상태 변경 시 데이터를 갱신합니다.

### Step 6. 디자인 개선
- 색상과 카드 디자인을 정리합니다.
- 인터랙션을 추가합니다.
- 모바일 반응형 스타일을 완성합니다.

### Step 7. 기능 검증
- 각 기능을 실제로 테스트합니다.
- 문제가 발생하면 원인을 파악하고 수정합니다.
- 전체 기능이 정상 작동하는지 확인합니다.

각 단계의 결과가 다음 단계와 연결되도록 진행하되, 별도의 승인 요청 없이 최종 결과물까지 구현해 주세요.

## [7단계] 최종 검증 및 완료 조건

다음 항목을 모두 충족하는지 확인해 주세요.

- [ ] 할 일 등록이 정상적으로 작동합니다.
- [ ] 내용이 없는 할 일은 등록되지 않습니다.
- [ ] 모든 태그를 선택할 수 있습니다.
- [ ] 태그별 필터가 정확하게 작동합니다.
- [ ] 완료 상태 필터가 정상 작동합니다.
- [ ] 두 필터를 함께 적용할 수 있습니다.
- [ ] 할 일 수정과 삭제가 가능합니다.
- [ ] 체크박스로 완료 상태를 변경할 수 있습니다.
- [ ] 진행 현황과 진행률이 정확하게 계산됩니다.
- [ ] 새로고침 후에도 데이터가 유지됩니다.
- [ ] 데스크톱과 모바일 모두에서 화면이 정상적으로 표시됩니다.

첫 실행 시에는 예시에서 제시한 4개의 할 일을 샘플 데이터로 표시해 주세요.

단, 기존 LocalStorage 데이터가 있다면 샘플 데이터를 다시 생성하지 말고 기존 데이터를 불러와야 합니다. 사용자가 모든 할 일을 삭제한 경우에도 샘플 데이터가 자동으로 복구되지 않아야 합니다.

최종적으로 프로젝트를 완성한 후 생성된 파일 목록, 구현된 기능 및 실행 방법을 간단하게 설명해 주세요.

목표는 시각적으로 깔끔하면서도 실제로 모든 기능이 작동하는 **태그 및 필터 기반 개인 할 일 관리 웹 위젯**을 완성하는 것입니다.
